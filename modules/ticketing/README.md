# @passripple/ticketing

**Kind:** module · **Level:** 2 (composite domain)

## Responsibility

Ticket lifecycle: issue, bind to the buyer's device key, assign an attendee, transfer, void.

## Owns

The `ticketing` database schema. No other module writes to it (rule R1).

- `ticketing.tickets`: one row per ticket, whatever its origin (`sale`, `courtesy`, `door_sale`). Its entry mode is copied from its type when it is issued, and the type must belong to its event. Only the status and binding change (`unsold` → `issued` or `void`; `issued` → `bound` or `void`; `bound` → `bound` or `void`), and no ticket is deleted. Its fallback code is exactly ten Crockford Base32 characters, generated by `@passripple/crypto`.
- `ticketing.ticket_bindings`: append-only history of the device keys a ticket was bound to, one row per key version, with its reason (`bind`, `transfer`, `recovery`).
- `ticketing.transfers`: free transfer offers (6.6), kept by the SHA-256 of the link's secret. One open offer per ticket; it expires, never outlives the event's start, and is void once the ticket moves to another key version. A claimed offer keeps the SHA-256 of the receiver's access token, which reaches that one ticket.

- `ticketing.outbox`: the domain events this module emitted, published by the relay in `workers/jobs` (ADR 0029).
- `ticketing.inbox`: the envelopes of the events this module handled, by id, so a second delivery changes nothing. Append-only.

There is no `redeemed` status: `redemption` records whether a ticket was used (invariant I1). Named attendees, whose documents must be encrypted at rest, arrive in Phase 7.

### Device binding (ADR 0016)

A ticket is issued unbound (no key, key version 0). Each binding moves it to the next key version: 1 for the first, then one more on each transfer or recovery, so a newer binding makes every older certificate stale. For every role, the owner included:

- the key version only moves up, by exactly one, and only when the key changes to another, non-null key;
- each key version has its row in `ticket_bindings`, written before the ticket moves to it, and no row is left without the ticket moving to it;
- the first binding and at most five rebindings: key version 6 is the last.

Whether a key is an acceptable Ed25519 point is checked by `@passripple/crypto`, which refuses to certify any other.

| Function | Who | What |
|---|---|---|
| `ticketing.issue(event, ticket_type, order, origin, code_human)` | system | Issues one ticket, unbound |
| `ticketing.issue_order(message, order, event, lines)` | system | Handles `order.paid`: issues the order's tickets, one per code the Worker drew, and emits `ticket.issued` for each. Idempotent by the message and by the order |
| `ticketing.bind(ticket, holder_pubkey, reason)` | system | Binds a ticket to a device key and returns its new key version. `bind` on an issued ticket; `transfer` or `recovery` on a bound one. Emits `ticket.bound` (`bind`, `recovery`) or `ticket.transferred` in the same transaction |
| `ticketing.offer_transfer(ticket, holder_pubkey, offer_token, ttl)` | system | Offers a ticket held by that key, cancelling any open offer; returns its expiry. The Worker checks the holder's signature first |
| `ticketing.cancel_transfer(ticket, holder_pubkey)` | system | Withdraws the ticket's open offer |
| `ticketing.transfer_offer(offer_token)` | system | What the receiver sees: event, type, expiry and state (`open`, `claimed`, `cancelled`, `expired`) |
| `ticketing.claim_transfer(offer_token, holder_pubkey, holder_token)` | system | Binds the ticket to the receiver's key (`transfer`) and records their access token |
| `ticketing.held_ticket(holder_token)` | system | The receiver's ticket, in the columns of `orders.wallet_tickets` |
| `ticketing.transferred_tickets(tickets)` | system | Which of these were ever transferred; the buyer's recovery skips them |
| `ticketing.void(ticket)` | organizer, admin | Voids a ticket, online only |

## Handles

`order.paid`, through `ticketing.issue_order`, called by the consumer in `workers/jobs` with the order's lines read from `orders`, which this module cannot read (rule R2).

## Emits

`ticket.issued` (through `ticketing.outbox` when issued for an order), `ticket.bound` (first binding and recovery), `ticket.transferred` and `ticket.voided` (see `@passripple/contracts`).

## Depends on

- `@passripple/contracts`
- `@passripple/crypto`
- `@passripple/events`
- `@passripple/catalog`

## Does not

Validate tickets at the gate, charge money, or send notifications.

## Public API

Everything other packages may use is exported from `src/index.ts`. Deep imports are not allowed.
